# Native packaging

Noire uses one staged filesystem layout for the Debian/Ubuntu and Fedora package
families. The split is deliberate:

- `noire-daemon` contains `noired`, `noirectl`, the user service, D-Bus metadata,
  configuration, user, troubleshooting, privacy, and security documentation,
  completions, and man pages, with no GTK dependency;
- `noire-ui` contains the optional GTK executable and desktop assets and depends
  on the matching daemon package;
- `noire` is an empty convenience package that installs both components.

Build all three release binaries first:

```sh
cargo build --release --locked --package noired --features pipewire-backend
cargo build --release --locked --package noirectl
cargo build --release --locked --package noire-ui --features gtk-ui
```

On Debian or Ubuntu, install `dpkg-dev` so runtime dependencies can be derived
from the finished ELF binaries, then run:

```sh
packaging/debian/build.sh 1.0.0-1 amd64 target/release dist/deb
```

On Fedora, run:

```sh
packaging/rpm/build.sh 1.0.0 x86_64 target/release dist/rpm
```

Release RPMs must be compiled on the Fedora 43 support floor so their generated
ELF requirements do not accidentally bind to a newer glibc. The reproducible
system-dependency image is `packaging/validation/Containerfile.release-fedora`;
its `FEDORA_VERSION` build argument defaults to 43. Mount the clean source and
the pinned Rust/Cargo homes into that image, build all three release binaries,
then run the RPM builder above inside the same container.

Set `NOIRE_RPM_RELEASE=2` (or another positive integer) when building a newer
package revision of the same application version. Debian revisions belong in the
first argument, for example `1.0.0-2`. Both builders reject placeholder scripts
and non-x86-64 ELF binaries unless the package smoke test explicitly enables its
test-only fixture escape hatch. Debian dependencies are derived from the finished
ELF binaries; RPM dependencies are generated by `rpmbuild`.

Package downgrade is permitted because root-level package scripts must not scan
or alter every user's home directory. Compatibility is enforced when each user's
daemon starts: a config schema newer than that binary supports produces the
`config-newer-schema` state, retains inactive safe defaults, rejects mutations as
read-only, and preserves the original file byte-for-byte. A compatible-schema
rollback proceeds normally. The disposable lifecycle harness exercises an actual
revision downgrade and the packaged-service harness proves the runtime refusal.

The builders do not install packages or modify user sessions. They consume
already-built native binaries and write artifacts only to the requested output
directory. Package install/remove scripts intentionally do not enter home
directories, restart user services, or delete user configuration. Before package
removal, the current user should run `noirectl stop` and disable launch at login.
Package purge also preserves per-user configuration by design; only that user
should explicitly remove `~/.config/noire` when desired.

## Packaged UI boundary

Run the short installed-UI matrix only in disposable containers. It verifies the
GTK-free daemon/CLI split, private D-Bus operation, GTK 4.10 minimum, explicit
no-display error, a three-second Xvfb window session, process cleanup, and
headless operation after removing `noire-ui`:

```sh
podman build -t localhost/noire-phase8-ubuntu:24.04 \
  -f packaging/validation/Containerfile.ubuntu .
podman run --rm --security-opt label=disable \
  --volume "$PWD:/workspace:ro" --workdir /workspace \
  --env NOIRE_PHASE8_DISPOSABLE_VM=1 \
  localhost/noire-phase8-ubuntu:24.04 \
  .github/scripts/run_phase8_packaged_ui_vm.sh deb dist/deb
```

Use `Containerfile.debian` with `debian:13` and the same Debian artifacts. For
the exact Fedora floor, build with `--build-arg FEDORA_VERSION=43`, then use the
`rpm` harness argument and `dist/rpm`; omit the build argument to retain Fedora
44 coverage. These bounded development checks do not replace signed-candidate
clean-VM qualification.

Refresh the AppStream overview image from a real running Debian package in the
Ubuntu fixture with:

```sh
podman run --rm --security-opt label=disable \
  --volume "$PWD:/workspace" --workdir /workspace \
  --env NOIRE_PHASE8_SCREENSHOT_VM=1 \
  localhost/noire-phase8-ubuntu:24.04 \
  .github/scripts/capture_phase8_appstream_screenshot.sh \
    dist/deb data/screenshots/noire-overview.png
python3 .github/scripts/validate_appstream_screenshots.py \
  data/metainfo/io.github.rayan6ms.Noire.metainfo.xml .
```

The harness starts a private PipeWire/D-Bus session and synthetic microphone,
captures the actual active GTK window with a software renderer, and emits a
stripped 1280×720 PNG. Visually inspect every refreshed image before use.

After creating baseline and upgrade revisions, exercise the bounded package
manager lifecycle only inside a disposable root environment:

```sh
NOIRE_PHASE9_DISPOSABLE_VM=1 \
  .github/scripts/run_phase9_package_manager_vm.sh deb dist/deb-1 dist/deb-2
```

Use `rpm` for Fedora-family artifacts. The harness checks headless and full
installs, direct shared-library resolution, revision upgrade and downgrade,
removal, reinstall, default-disabled service state, absence of package-owned home
files, and byte-for-byte preservation of current and future-schema user
configuration. The integrated login, running-daemon, PipeWire-node, and signed-
candidate qualification remains required before release.

Lint real Fedora artifacts with the narrowly scoped metapackage exceptions:

```sh
rpmlint -r packaging/rpm/rpmlintrc dist/rpm/*.rpm
```

The installed-service slice requires a disposable environment booted with
systemd as PID 1. Build one of the Debian-family fixtures and run the gated
harness there:

```sh
podman build -t localhost/noire-phase9-ubuntu:24.04 \
  -f packaging/validation/Containerfile.ubuntu .
podman run --detach --name noire-phase9-packaged-service \
  --systemd=always --security-opt label=disable \
  --volume "$PWD:/workspace:rbind" localhost/noire-phase9-ubuntu:24.04
podman exec --workdir /workspace --env NOIRE_PHASE9_DISPOSABLE_VM=1 \
  noire-phase9-packaged-service \
  .github/scripts/run_phase9_packaged_service_vm.sh deb dist/deb
```

For Debian 13, replace the image build with:

```sh
podman build -t localhost/noire-phase9-debian:13 \
  -f packaging/validation/Containerfile.debian .
```

Then use that image in the same `podman run` command. Ubuntu-built `.deb`
artifacts are intentionally accepted by this Debian fixture only when their
declared runtime dependencies resolve there.

Stop and remove only this disposable container after the run. The harness proves
package ownership, eight-client D-Bus activation convergence, opt-in login activation,
same-user execution, exactly one live PipeWire source, zero sources after an
explicit stop, newer-schema read-only refusal, uninstall, and configuration
preservation. Use `Containerfile.fedora`, the `rpm` harness argument, and an RPM
artifact directory for the Fedora-family equivalent. The bounded development
matrix is Ubuntu 24.04, Debian 13, Fedora 43, and Fedora 44; repeat it with signed
artifacts in clean VMs before release.

## Release metadata

Generate the release checksum manifest, SPDX 2.3 SBOM, third-party notice
inventory, and SLSA provenance statement from the final native artifacts:

```sh
SOURCE_DATE_EPOCH=$(git show -s --format=%ct HEAD) \
  packaging/generate-release-metadata.py generate \
    --version 1.0.0 \
    --artifact-dir dist/deb \
    --artifact-dir dist/rpm \
    --artifact-dir dist/source \
    --output-dir dist/release-metadata
```

The generator resolves the release dependency closure from `Cargo.lock` in
offline mode, verifies the embedded RNNoise weights digest, rejects symlinks and
unrecognized artifact types, and refuses a dirty source tree. It emits
`SHA256SUMS`, `noire-<version>.spdx.json`, `THIRD_PARTY_LICENSES.md`, and
`noire-<version>.intoto.jsonl`. The provenance subjects are the native artifacts;
the checksum manifest also covers all three metadata files. Signing is purposely
deferred until these files belong to a frozen release candidate. The provenance
field contract and exact assembly invocation are versioned in
[`release-metadata-build-v1.md`](release-metadata-build-v1.md).

Verify the generated set independently before signing or publishing it:

```sh
packaging/generate-release-metadata.py verify \
  --version 1.0.0 \
  --artifact-dir dist/deb \
  --artifact-dir dist/rpm \
  --artifact-dir dist/source \
  --metadata-dir dist/release-metadata
```

`NOIRE_RELEASE_ALLOW_DIRTY_SOURCE=1` is only a development-fixture escape hatch;
never use it for release candidates.

## Candidate freeze audit

The first 1.0 candidate is defined by
[`release-candidate-freeze-v1.md`](release-candidate-freeze-v1.md). Before any
tag, signature, upload, or publication, build its exact package set from one
clean commit and run:

```sh
python3 .github/scripts/audit_release_candidate.py \
  --expected-version 1.0.0 --package-release 1 \
  --deb-dir dist/deb --rpm-dir dist/rpm \
  --source-dir dist/source --metadata-dir dist/release-metadata
```

The audit deliberately fails development packages, stale package metadata,
dirty source, version drift, and Git-sourced dependencies. A passing freeze
audit does not itself satisfy later qualification. For 1.0.0, the owner stopped
after the completed eight-hour run and explicitly waived the remaining human,
clean-VM, application, signed-lifecycle, idle-resource, and final-soak gates.
See [`tests/release/qualification-decision-1.0.0.toml`](../tests/release/qualification-decision-1.0.0.toml).
Waived evidence must not be reported as passed.
